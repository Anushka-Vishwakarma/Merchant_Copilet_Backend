# 5. Order Item Data

One order can contain multiple products.

So don't put everything directly inside the `orders` table.

You need a separate **OrderItem** concept.

Example:

```text
Order
  │
  ├── OrderItem 1 → Product A × 2
  ├── OrderItem 2 → Product B × 1
  └── OrderItem 3 → Product C × 4
```

Data to investigate:

* Order item ID
* Order ID
* Product ID
* Variant ID
* Quantity
* Unit price
* Discount
* Tax
* Line total

WooCommerce's order API, for example, includes line items with product references and quantities. ([The WooCommerce Developer Blog][4])

# 19. One very important API research finding

While researching the current APIs, there is a significant thing you should record in your **Data Requirements document**:

**Shopify order-history access has an access-scope consideration.** Shopify's current documentation says the Order object requires appropriate order-related access scopes, and older orders beyond the default recent window require additional access. ([Shopify][3])

WooCommerce's current recommended REST API is **v3**, and its REST API provides resources such as customers, orders and products in JSON. ([The WooCommerce Developer Blog][6])

So your research sheet should have a column:

> **“Available through official API + required permission/scope”**

That prevents you from designing your database around data that your application cannot actually obtain.
