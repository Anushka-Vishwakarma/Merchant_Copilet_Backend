For **WooCommerce**, use the same research method as Shopify, but the current official API is a little different: WooCommerce recommends the **REST API v3** for new integrations, using `/wp-json/wc/v3/` endpoints. It provides resources such as customers, orders, products, payment gateways, shipping zones, and webhooks. ([The WooCommerce Developer Blog][1])

## 1. Main WooCommerce data you need

For Merchant Co-Pilot, investigate these resources:

| WooCommerce resource    | Merchant Co-Pilot use            |
| ----------------------- | -------------------------------- |
| **Customers**           | Customer history + churn         |
| **Orders**              | Main commerce data + RTO         |
| **Order line items**    | Products purchased               |
| **Products**            | Product information              |
| **Refunds**             | Order outcome/financial analysis |
| **Payment information** | RTO/payment features             |
| **Shipping/Billing**    | Geography                        |
| **Webhooks**            | Continuous synchronization       |

## 2. Customer data

Research the **Customers API** and record:

```text
Customer
├── Customer ID
├── Date created
├── Date modified
├── Email
├── Name
├── Billing information
├── Shipping information
├── Number of orders
└── Total spent
```

WooCommerce's customer API exposes customer information including ID, dates, email, billing/shipping information, order count and total spent. ([The WooCommerce Developer Blog][2])

Then Merchant Co-Pilot can **calculate**:

```text
total_orders
total_spend
first_order_date
last_order_date
recency
frequency
monetary_value
average_order_value
previous_rto_count
```

Those calculated values are your **features**, not raw WooCommerce data.

# 8. Order status vs RTO

This is an important research point.

WooCommerce has standard order statuses such as:

```text
pending
processing
on-hold
completed
cancelled
refunded
failed
trash
```

([The WooCommerce Developer Blog][3])

But **RTO is not automatically the same thing as one of those standard statuses**.

So don't design:

```text
status = RTO
```

without investigating the actual merchant workflow.

Instead, your integration should eventually normalize source information into something like:

```text
delivery_outcome
----------------
DELIVERED
RTO
RETURNED
CANCELLED
UNKNOWN
```

Only mark something as RTO when your source/integration actually provides enough evidence.

# 10. Webhooks — very important for production

WooCommerce supports webhooks for:

* Customer created/updated/deleted
* Order created/updated/deleted
* Product created/updated/deleted

([The WooCommerce Developer Blog][5])

The webhook payload for API resources is JSON, and WooCommerce includes an HMAC-SHA256 signature so your application can verify the payload. ([The WooCommerce Developer Blog][5])

So your production synchronization can be:

```text
WooCommerce
     │
     ├── REST API
     │      ↓
     │   Historical data
     │
     └── Webhooks
            ↓
        New/updated data
            ↓
     Merchant Co-Pilot
            ↓
       PostgreSQL
```

# 11. Pagination

When downloading historical data, you cannot assume one API request returns everything.

WooCommerce's REST API supports pagination using parameters such as `per_page` and `page`; response headers provide total resources and total pages. ([The WooCommerce Developer Blog][6])

So your integration needs:

```text
Request page 1
      ↓
Request page 2
      ↓
Request page 3
      ↓
...
      ↓
All required historical records
```

This matters for your RFM, churn and previous-RTO calculations.

# 12. Authentication

For your research, record **how Merchant Co-Pilot authenticates with each store**.

WooCommerce's REST API uses authenticated API access, and the official documentation describes REST API authentication and HTTPS usage. ([The WooCommerce Developer Blog][6])

Your database should **not store raw API secrets casually**.

Your project already requires integration credentials to be protected/encrypted and tenant-scoped.

### The key research conclusion

For WooCommerce, your first-party source data should primarily be researched through:

**REST API v3 → Customers + Orders + Products + Order items + payment/order information + shipping + refunds + Webhooks.**

The current official documentation explicitly identifies REST API v3 as the recommended version for new integrations. ([The WooCommerce Developer Blog][1])

After this, you have enough information to make the **Shopify vs WooCommerce comparison/data-mapping table**, which is the step immediately before designing your common Merchant Co-Pilot database.
