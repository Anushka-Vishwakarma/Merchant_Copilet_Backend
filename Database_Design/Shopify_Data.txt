# 9. Historical order data — VERY important

This is something you should put in your research report with a red warning.

Shopify's current documentation says the Order query provides the **last 60 days of orders by default**. Accessing older orders requires additional access to all orders. Shopify also recommends bulk operations for large datasets. ([Shopify][1])

That's important because your Merchant Co-Pilot needs **historical customer behavior** for RFM, churn and previous RTO features.

So your requirement becomes:

> **Historical order access must be verified before implementing customer-history-based ML.**

# 10. How do we get lots of Shopify data?

Shopify uses **cursor-based pagination** for GraphQL connections. The documented maximum for retrieving resources through a connection is 250 at a time; bulk operations are available for larger datasets. ([Shopify][5])

So your architecture should be:

```text
Shopify
   ↓
GraphQL Admin API
   ↓
Pagination / Bulk Operations
   ↓
Integration Service
   ↓
Normalize
   ↓
PostgreSQL
```

Not:

```text
Shopify → directly into ML
```

---

# 11. How do we get NEW orders?

For ongoing synchronization, Shopify provides **webhooks**.

For example, Shopify documents an `orders/create` webhook that sends a payload to your application when an order is created. Webhooks can also be used for other resource changes. ([Shopify][6])

Your production architecture can therefore be:

```text
                 ┌── Historical data
Shopify ─────────┤
                 │
                 └── Webhooks for changes
                           ↓
                    Integration Service
                           ↓
                     Normalization
                           ↓
                       PostgreSQL
```

Shopify also recommends verifying webhook HMAC signatures and handling duplicate deliveries. ([Shopify][6])

# 13. Rate limits

Your production design also needs to account for Shopify API limits.

The GraphQL Admin API uses a **query-cost-based rate limit**, rather than simply “X requests per minute.” Shopify currently documents different restore rates by plan. ([Shopify][7])

Therefore your integration should have:

```text
API Request
    ↓
Rate-limit check
    ↓
Request
    ↓
If throttled
    ↓
Wait / retry
```

Shopify also recommends requesting only the data your application needs, caching where appropriate, regulating requests and handling errors. ([Shopify][8])
